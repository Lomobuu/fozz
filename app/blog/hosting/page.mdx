# Host a Static Website Using Azure Storage and Azure Front Door

Hosting a static website in Azure can be both cost‑efficient and highly scalable.  
This guide walks through deploying a static site to an Azure Storage Account, automating deployment with GitHub Actions, and configuring a custom domain through Azure Front Door and GoDaddy.

---

## Prerequisites

- Azure Subscription  
- GitHub repository containing your static site (React/Next.js/etc.)  
- Azure Service Principal (via OIDC)  
- Azure Storage Account with **Static Website** enabled  

---

## Service Principal (OIDC Authentication)

A Service Principal acts as the identity GitHub Actions uses to deploy resources.  
Instead of storing long‑lived secrets, we use **OIDC authentication**, which allows GitHub to request short‑lived Azure tokens securely.

Grant the Service Principal the minimum permissions needed.

## Add Azure IDs to GitHub Secrets

GitHub Actions requires three identifiers:

- **AZURE_CLIENT_ID** – Service Principal ID  
- **AZURE_TENANT_ID** – Azure AD tenant  
- **AZURE_SUBSCRIPTION_ID** – Subscription to deploy into  

These are identifiers only — not sensitive secrets.

# Create Static Website in Azure Storage (Terraform)

Refer to:  
**[Simple Terraform state storage in Azure](/blog/tfstate)**

Add the following resource definitions:

### strg.tf

```hcl:strg.tf
resource "azurerm_storage_account" "storageAccount" {
  name                     = local.strg_name
  resource_group_name      = azurerm_resource_group.rg.name
  location                 = azurerm_resource_group.rg.location
  account_tier             = "Standard"
  account_replication_type = "GRS"
}

resource "azurerm_storage_account_static_website" "website" {
  storage_account_id = azurerm_storage_account.storageAccount.id
  error_404_document = "404.html"
  index_document     = "index.html"
}
```

## Deploy static website with GitHub actions workflow
This workflow builds your React app and uploads the output to the $web container.

```yaml:deploy.yaml
name: Deploy React App to Azure Storage

on:
  push:
    branches:
      - main # Trigger on pushes to the main branch

permissions:
  id-token: write
  contents: read

env:
    STORAGE_ACCOUNT: fozzstrg # Hardcoded in this example to comply with manual & terraform storage creation

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20.9.0' # Use your desired Node.js version

      - name: Install dependencies and build
        run: |
          npm install
          npm run build # This command generates the static files in the 'build' directory (default for Create React App)

      - name: Azure Login
        uses: azure/login@v1
        with:
          client-id: ${{ secrets.AZURE_CLIENT_ID }}
          tenant-id: ${{ secrets.AZURE_TENANT_ID }}
          subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}

        - name: Upload to Azure Blob Storage
          uses: azure/CLI@v1
          with:
            inlineScript: |
              az storage blob delete-batch --account-name $STORAGE_ACCOUNT --source '$web' --pattern "*"
              az storage blob upload-batch --account-name $STORAGE_ACCOUNT --source out --destination '$web'
```

# Azure Front Door

## Create Azure Front Door (Terraform)

Defer to [Simple Terraform state storage in Azure](/blog/tfstate)

Add the following resource

### frontdoor.tf

```hcl:frontdoor.tf
resource "azurerm_cdn_frontdoor_profile" "frontDoor" {
  name                = local.frontdoor_name
  resource_group_name = azurerm_resource_group.rg.name
  sku_name            = "Standard_AzureFrontDoor"
}
```
