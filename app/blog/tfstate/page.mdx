# Simple Terraform state storage in Azure

<BlogImage 
  src="/terraformazure.png" 
  alt="Terraform & Azure"
  size="large" 
/>

---

<br/>
Terraform state is a file that records the infrastructure resources Terraform manages and maps them to your real cloud environment.
Storing the state locally can easily lead to conflicts, especially when multiple developers or automation pipelines interact with the same infrastructure. Local files also introduce risks such as accidental deletion, overwriting, or inconsistent versions.
<br/>
By storing state remotely in Azure — typically inside an Azure Storage Account — you enable centralized, secure, and versioned state management. Remote state also adds capabilities such as state locking, preventing two operations from making changes simultaneously.
<br/>
This setup becomes even more important when using CI/CD pipelines like GitHub Actions, where automated workflows must securely retrieve and update the shared Terraform state.
<br/>

## Goal Dataflow: GitHub to Azure Dataflow
The ideal scenario is a fully automated pipeline:
<br/>
GitHub Actions runs Terraform → authenticates via Federated Identity → reads/writes state in Azure → applies changes.
<br/>
This removes local machine dependencies entirely. Infrastructure becomes reproducible and consistent, and deployments are performed in a controlled CI/CD environment.
<br/>
Moving the local storage to Azure introduces a remote backend, giving you:
- **Shared access for teams** | Everyone reads and writes from the same state file.
- **Locking** | Azure Storage provides blob leases, preventing parallel updates.
- **Versioning** | Storage Accounts automatically keep previous state versions if enabled.

### Create Storage Account & Container via GitHub Actions workflow

This workflow automates the creation of the backend resources.
Running this once ensures that all required Terraform backend components are consistently deployed.
You only need to adjust:

- Resource group name
- Storage account name

The rest is handled automatically through Azure CLI commands.

```yaml:title=backend.yaml
on: workflow_dispatch # Manual start trigger

name: BackendStorageCreate

permissions:
  id-token: write # Require write permission to Fetch an OIDC token.

env:
  location: "westeurope"
  terraformStorageRG: <name of resource group>
  terraformStorageAccount: <name of storage account> # no dashes allowed
  containerNameBackend: 'tfstate' # Name of container
  backendAzureRmKey: 'terraform.tfstate'

jobs:

  setup-terraform-backend:
    runs-on: ubuntu-latest
    steps:
    - name: Azure Login
      uses: azure/login@v2
      with:
        client-id: ${{ secrets.AZURE_CLIENT_ID }}
        tenant-id: ${{ secrets.AZURE_TENANT_ID }}
        subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}

    - name: Azure CLI script
      uses: azure/cli@v2
      with:
        azcliversion: latest
        inlineScript: |
          az group create --location $location --name $terraformStorageRG
          
          az storage account create --name $terraformStorageAccount --resource-group $terraformStorageRG --location $location --sku Standard_LRS
          
          az storage container create --name $containerNameBackend --account-name $terraformStorageAccount
```

## Run Terraform with GitHub Actions

This section configures Terraform so that GitHub Actions performs all deployment steps: init, validate, plan, and apply.
By referencing the resource group and storage account created earlier, Terraform can connect to the remote backend automatically.

### main.tf
```hcl:main.tf
terraform {
  required_providers {
    azurerm = {
      source = "hashicorp/azurerm"
      version = "~> 4.6.0"
    }
  }
}

provider "azurerm" {
   features {}
   use_oidc = true
}

# Resource Group
resource "azurerm_resource_group" "rg" {
  name     = local.rg_name
  location = var.location
}
```
### variables.tf
```hcl:variables.tf
variable "env" {
  type = string
  default = "test"
}

variable "location" {
  type        = string
  default = "westeurope"
}
```
### locals.tf
```hcl:locals.tf
locals {
  # Make sure the name is lower case
  env = lower(var.env)

  # Your base project name
  base = "simpletst"

  # Resource Group Name (may contain dashes)
  rg_name = "${local.base}-RG-${local.env}"

}
```
### terraform.yaml
The workflow handles:

OIDC authentication
Terraform initialization with backend config
Formatting, validation, planning
Auto-apply for changes on main

This creates a fully automated GitOps-style deployment pipeline.

```yaml:terraform.yaml
name: 'Terraform Plan & Apply'

on:
  push:
    branches: # Trigger on main branch
      - main 
    paths: # Only trigger if infrastructure is changed
    - '.github/Terraform/**'
    - '.github/workflows/terraform.yaml'
  workflow_dispatch: # Optional manual trigger


permissions:
  id-token: write
  contents: read

env:
    ARM_CLIENT_ID: ${{ secrets.AZURE_CLIENT_ID }} # Terraform uses variable implicit to authenticate
    ARM_SUBSCRIPTION_ID: ${{ secrets.AZURE_SUBSCRIPTION_ID }} # Terraform uses variable implicit to authenticate
    ARM_TENANT_ID: ${{ secrets.AZURE_TENANT_ID }} # Terraform uses variable implicit to authenticate
    location: westeurope
    RESOURCE_GROUP: <resource group name> # same as backend.yaml
    STORAGE_ACCOUNT: <name of storage account where tfstate is stored> # same as backend.yaml

jobs:
  terraform:
        name: Deploy to Azure
        runs-on: ubuntu-latest
        # Use the Bash shell regardless whether the GitHub Actions runner is ubuntu-latest, macos-latest, or windows-latest
        defaults:
          run:
            working-directory: .github/Terraform
            shell: bash

        steps:
        # Checkout the repository to the GitHub Actions runner
        - name: Checkout
          uses: actions/checkout@v3

        # Install the latest version of Terraform CLI 
        - name: Setup Terraform
          uses: hashicorp/setup-terraform@v1

        # Initialize a new or existing Terraform working directory by creating initial files, loading any remote state, downloading modules, etc.

        - name: Terraform Init
          run: |
            terraform init \
              -backend-config="resource_group_name=$RESOURCE_GROUP" \
              -backend-config="storage_account_name=$STORAGE_ACCOUNT" \
              -backend-config="container_name=tfstate" \
              -backend-config="key=terraform.tfstate" \
              -backend-config="use_oidc=true"


        - name: Terraform Format
          run: terraform fmt -recursive

        # Validate before Planning
        - name: Terraform Validate
          run: terraform validate 


        - name: Terraform Plan
          run: terraform plan -input=false -var location=$location
          
        - name: Terraform Apply
          run: terraform apply -auto-approve -input=false -var location=$location
```
